# Scenario Files

A scenario file is a JSON document that completely describes one simulation run. The program reads it at startup — nothing about the simulation is hardcoded outside of `scenarios/default.json`.

Scenario files are designed to be generated by LLMs, scripts, or search algorithms. Generate a file, run it, collect the JSON result.

---

## Running a scenario

```bash
# Interactive display, default scenario
python main.py

# Interactive display, custom scenario
python main.py --scenario scenarios/asymmetric.json

# Headless (no window), print summary
python main.py --scenario scenarios/my_scenario.json --headless

# Headless, write full results to file
python main.py --scenario scenarios/my_scenario.json --headless --output results/run_001.json

# Headless via the scenario file itself (set "headless": true inside the file)
python main.py --scenario scenarios/my_scenario.json
```

`--headless` and `--output` override whatever the scenario file says. This lets you keep a scenario file headless-agnostic and control output from the command line.

## Complete field reference

```jsonc
{
  // Human-readable labels — used in result output and window title
  "name":        "My Scenario",       // string, required
  "description": "What this tests",  // string, optional

  // BoundsModule radius for all ships — ships repel toward centre when
  // outside 80% of this distance. Should comfortably contain all spawn
  // centres plus expected movement range.
  "world_bounds": 2000,               // float, default 2000

  // One entry per faction.  Minimum one faction.  IDs must be unique.
  "factions": [ /* see Faction block */ ],

  // Obstacle field placed before ships spawn
  "obstacles": { /* see Obstacles block */ },

  // Episode termination and output settings
  "simulation": { /* see Simulation block */ }
}
```

### Faction block

```jsonc
{
  "id": 0,                  // int, required — must match factions.py color index
                            //   0=green  1=red  2=blue  3=yellow
  "ship_count": 30,         // int, required
  "spawn_center": [-400, 0],// [x, y], required — world-space spawn point
  "spawn_radius": 150,      // float, default 150 — ships scatter within this radius

  // Where this faction is trying to go.
  // Omit "objective" entirely, or set "position": null, for no objective.
  "objective": {
    "position": [400, 0],   // [x, y] world coords, required for area objective
    "patrol_radius": 200    // float, default 200 — orbit ring radius
  },

  // Ship stat overrides — all fields optional, missing fields use engine defaults
  "ship": {
    "max_speed":            100,   // px/s
    "forward_acceleration":  40,   // px/s²
    "brake_acceleration":   200,   // px/s²
    "turn_rate":            180,   // deg/s
    "lateral_damping":      3.0,   // exponential sideways drag coefficient
    "hp":                   100,   // hull points (0 = destroyed)
    "shield":               200,   // absorbs damage before HP; 0 = no shield
    "shield_regen":           0,   // shield points recovered per second; 0 = no regen
    "size":                  10,   // render radius and collision radius in px
    "visual_range":         800    // target acquisition range in px
  },

  // Weapon stat overrides — all fields optional
  "weapon": {
    "range":           400,  // px — maximum fire distance
    "damage":           10,  // HP per shot
    "fire_rate":         5,  // shots/sec within a cassette
    "max_fire_angle":   25,  // half-cone degrees — arc within which the weapon fires
    "cassette_size":     5,  // shots before a reload is triggered
    "reload_duration":   6   // seconds for a full reload
  },

  // Weight policy for every ship in this faction.
  // One Personality instance is shared across all ships in the faction.
  // "default"          — built-in ammo-state rotation (reload=retreat, loaded=attack)
  // "none"             — no overrides; all module static weights apply every frame
  // "ml:<path>"        — load MLPersonality from a .npz weights file
  "personality": "default"
}
```

### Obstacles block

```jsonc
"obstacles": {
  "enabled":          true,   // bool, default true — set false for open field scenarios
  "count":              14,   // int — target number of obstacles to place
  "min_size":           60,   // float — minimum obstacle radius in px
  "max_size":          110,   // float — maximum obstacle radius in px
  "world_half_x":     1400,   // float — placement area half-width
  "world_half_y":      800,   // float — placement area half-height
  "spawn_clearance":   300,   // float — obstacles stay at least this far from each spawn_center
  "seed":             null    // int | null — null = random per run; integer = reproducible layout
}
```

Obstacles are placed with a Poisson-disk algorithm that guarantees no two obstacles are close enough that a ship could be simultaneously inside the soft-avoidance radius of both. Setting `"seed"` to an integer makes the layout reproducible across runs — useful when isolating the effect of a personality change from map variation.

### Simulation block

```jsonc
"simulation": {
  "max_steps": null,    // int | null — null runs until one faction is eliminated;
                        // set a number to cap episode length (e.g. 18000 = 5 min at 60fps)
  "headless": false,    // bool — true skips display; overridden by --headless CLI flag

  "output": {
    "file": null,             // string | null — path to write result JSON; null = no file
                              //   overridden by --output CLI flag
    "record_interval": 60     // int — steps between timeline snapshots; 0 = no timeline
  }
}
```

## Result file format

When a headless run completes and `output.file` is set, this JSON is written:

```jsonc
{
  "scenario":  "My Scenario",
  "timestamp": "2024-03-15T14:30:22Z",  // UTC ISO-8601

  "outcome": {
    "winner":            0,       // int | null — faction id of winner; null = draw/timeout
    "draw":              false,   // true when multiple factions survive at episode end
    "steps":             1842,    // total simulation steps
    "simulated_seconds": 30.7     // steps / 60
  },

  // Per-faction ship counts
  "factions": {
    "0": { "initial": 30, "remaining": 12 },
    "1": { "initial": 30, "remaining": 0  }
  },

  // Faction counts at each recorded step (empty array if record_interval = 0)
  "timeline": [
    { "step":   0, "factions": { "0": 30, "1": 30 } },
    { "step":  60, "factions": { "0": 29, "1": 28 } },
    { "step": 120, "factions": { "0": 28, "1": 26 } }
  ]
}
```

## Designing scenarios for data collection

### Reproducible runs

Set `obstacles.seed` to a fixed integer. Otherwise the asteroid field is random each run and ship counts at a given step will vary due to map effects rather than AI behaviour.

```json
"obstacles": { "seed": 42, ... }
```

### Capping episode length

Open-ended runs (no `max_steps`) can last indefinitely if both sides reach a stalemate near their objectives. Cap with `max_steps` when collecting batches:

```json
"simulation": { "max_steps": 10800, "headless": true }
```

10800 steps = 3 minutes at 60fps — long enough for most encounters to resolve.

### Timeline granularity

`record_interval: 60` gives one snapshot per simulated second (60 steps = 1s at 60fps). For high-resolution survival curves use `30`; for lightweight batch runs use `300` or `0` to disable the timeline entirely.

### Testing a specific personality

Set the faction you want to test and use `"none"` on the opponent so static weights act as a neutral baseline:

```json
"factions": [
  { "id": 0, "personality": "ml:models/candidate.npz", ... },
  { "id": 1, "personality": "none", ... }
]
```

### Multi-faction free-for-all

Add more faction objects. Faction IDs map to colours: 0=green, 1=red, 2=blue, 3=yellow. Each faction's objective should point somewhere meaningful — the others' spawn centres, a shared central point, or omitted entirely for pure combat.

```json
"factions": [
  { "id": 0, "spawn_center": [-500,  300], "objective": { "position": [0, 0] }, ... },
  { "id": 1, "spawn_center": [ 500,  300], "objective": { "position": [0, 0] }, ... },
  { "id": 2, "spawn_center": [   0, -500], "objective": { "position": [0, 0] }, ... }
]
```

## Batch runner example

Run the same scenario N times with different random seeds and aggregate win rates:

```python
import json, subprocess, sys
from collections import Counter

SCENARIO = "scenarios/asymmetric.json"
RUNS     = 50

wins = Counter()
for i in range(RUNS):
    result = subprocess.run(
        [sys.executable, "main.py",
         "--scenario", SCENARIO,
         "--headless",
         "--output", f"/tmp/run_{i}.json"],
        capture_output=True, text=True,
    )
    with open(f"/tmp/run_{i}.json") as f:
        data = json.load(f)
    winner = data["outcome"]["winner"]
    wins[winner if winner is not None else "draw"] += 1

print(f"Results over {RUNS} runs:")
for faction, count in sorted(wins.items(), key=lambda x: -x[1]):
    print(f"  Faction {faction}: {count} wins ({100*count/RUNS:.0f}%)")
```

Or call `simulation.run_scenario()` directly in-process for faster iteration (no subprocess overhead):

```python
from scenario import load_scenario
from simulation import run_scenario

config = load_scenario("scenarios/asymmetric.json")
config.obstacles.seed = None          # random map each run
config.simulation.output.file = None  # no file output, just use return value

wins = Counter()
for _ in range(50):
    result = run_scenario(config)
    wins[result["outcome"]["winner"]] += 1
```
